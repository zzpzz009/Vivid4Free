# 外壳契约改造：体量与验收

本次目标是固定现有 UI/宿主边界，便于独立测试与后续替换宿主。原有 22 个请求、2 个推送事件及 UI 端 22 条 HTTP 路由保持不变；收尾补齐 7 条命名 Agent 路由，Agent 路由由 9 条增至 16 条。默认仍为 17860/17861 双端口，不切换外壳。

## 体量与复杂度

整体属于中等规模、兼容验证要求较高的重构。通道数量有限，核心困难是保留返回联合类型、取消行为、事件退订、任务幂等与提交结果未知状态，以及两个端口不同的鉴权条件。

改造提交 `8d17144` 涉及 24 个文件，新增 1,526 行、删除 209 行。其中规范与清单 336 行，测试约 637 行，架构检查工具 222 行；生产代码约新增 327 行、删除 205 行。大部分增量用于固定和验证行为，未引入新的运行时依赖。

如按人工工程排期，建议为同等范围预留 1–2 人日梳理和接入、1–2 人日兼容验收；这是工作量估算，不是本轮实际耗时或交付承诺。新宿主实现、统一旧接口错误格式、正式签名安装器及多电脑回归应另行估算。
