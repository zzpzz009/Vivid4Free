# 新电脑接入与更新 引擎

客户端与引擎独立安装。先登录 VividAI 账号，没有账号可从全屏登录页打开官方注册。验证成功后播放开屏，再进入工作区；未安装引擎时提示“更新与安装”，也可从标题旁的更新提示打开。右侧引擎区域仅显示连接状态，不再重复提供更新入口。

## 首次使用

- **已有官方引擎目录**：点击“接入已有环境”，选择直接含 `runtime.json`、`python`、`comfyui`、`models` 的版本目录，例如 `VividCFRuntime/versions/vivid-comfy-0.3.0`。无需复制大模型，也无需手工编辑设置。普通 ComfyUI 目录不属于此入口支持的运行包。
- **拿到官方离线 ZIP**：点击“导入 ZIP 并安装”，首次导入会先选择客户端安装目录及用户数据目录以外的独立存储位置。导入直接读取所选 ZIP，不额外复制归档；按解压空间检查磁盘，逐文件校验后接入。原始 ZIP 保留。
- **从网盘下载**：客户端启动时检查已配置的发布信息，标题旁区分提示“客户端可更新”“引擎可更新”或二者都有新版。在“更新与安装”面板查看本次更新内容和兼容要求，选择夸克网盘入口（百度网盘暂未开放，按钮置灰），使用网盘官方客户端下载 ZIP，完成后返回客户端，点击“导入 ZIP 并安装”。无需解压，客户端自动校验、安装并切换。

首次完整校验需要读取全部模型，耗时与磁盘速度有关。校验和安装期间请等待操作完成。接入后自动启动引擎，并检查当前客户端预览和放大需要的模型、节点及采样器；检查通过才显示“已就绪”。这项兼容检查不能替代真实出图验收。

选择会保存在本机用户数据中，重启后恢复。下载／更新存储位置和当前运行目录分别显示；更换未来的下载位置不会取消已接入的引擎。

没有在线地址时，也可把当前验收过的整个引擎版本目录复制到新电脑的独立位置后接入，包括清单、Python、插件和模型；只复制模型或旧电脑的设置文件不能完成接入。目标电脑仍须实际完成启动及出图验证。

## 更新与恢复

每次引擎发布同时准备全量 ZIP 和从上一正式版升级的增量 ZIP。首次安装、跨版本升级或本地文件被修改时使用全量包；只有已安装版本与增量基线一致时才推荐增量包。面板会显示建议类型与大小，下载后仍用同一个“导入 ZIP 并安装”入口。引擎包和模型只放夸克；客户端安装包和不含执行载荷的版本公告可放 GitHub。

增量包只携带新增、修改文件及删除清单；如果模型变化，对应模型也必须带入。导入先核对发布归档校验值、基础版本清单 SHA256 和基础文件，再在独立目录组合新版并逐文件校验。未变化文件复制到新版目录，下载量减少，但仍需要完整新版的本地磁盘空间；不使用会让新版修改影响旧版的硬链接。旧版日志、输出、额外模型和用户数据不被复制或删除。基础版本不符、文件损坏或空间不足时拒绝安装，提示改用全量包。

客户端 0.6.1 对应的新引擎为 0.3.2；首次增量基线为官方 0.3.1 全量包。0.3.2 两种包均不包含产品明文工作流，旧基线中的工作流文件只从新版目录排除，旧版回退目录保持原样。

面板同时显示客户端版本、已安装引擎版本、当前客户端支持的引擎版本，以及可下载新版引擎支持的客户端版本。客户端更新入口下载客户端安装程序，引擎更新入口下载独立 ZIP，两者分别发布。

发布公告的可选 `releaseNotes` 为引擎更新说明数组；可选 `clientRelease` 包含已发布客户端的 `version`、官方 `downloadUrl`、`notes` 数组及 `supportedRuntimeVersions`。客户端与引擎共用一次清单读取，仅在远端版本严格较新时提示更新；未提供客户端发布信息或网络失败时，不声称客户端已是最新版。客户端新版卡片提供安装包下载入口，安装仍须关闭客户端后覆盖安装。引擎已经匹配且无新版时，下载区收起，已有 ZIP 仍可从高级选项导入。

兼容判断先检查引擎标识、协议和平台，任一不匹配均拒绝。协议与平台匹配后，客户端自带 `client-runtime-policy.json` 中的 `supportedRuntimeVersions` 可明确支持既有引擎，即使旧发布清单及 ZIP 内的 `compatibleClientVersions` 没有登记新客户端补丁版本，也无需重写原 ZIP。引擎发布清单明确列出当前客户端时，同样认可该组合。两侧均未认可的组合显示“兼容性待验证”，不会直接声称已确认不兼容，也不自动放行未知版本。客户端 0.7.0 支持引擎 0.3.0 与 0.3.2；0.3.2 的协议、启动器与关键节点已和本机可用环境核对，实际安装后仍检查当前工作流所需模型、节点及采样器，失败时回退。协议与依赖检查不能替代真实出图验收。

旧的引擎 0.3.0 仅认可预览流程修正版，现存旧 ZIP 不属于已验收组合。兼容版本声明不能替代引擎工作流检查与真实出图验收。

已获取发布信息时，导入先核对 ZIP 大小和 SHA256，再核对内部版本与兼容关系，之后安全解压并校验全部文件。损坏包、版本不符和不兼容包不会替换当前环境。没有发布信息时仍可导入已有 ZIP，但界面明确说明此时只核对包内清单与文件，不能声称已与正式发布归档匹配。

同版不重复下载，数值版本较旧的包不会替换现用环境。正式引擎内容发生变化时必须发布新的独立引擎版本，不能只覆盖同名 ZIP；客户端版本不要求同步递增。

新版先在独立版本目录准备完成。切换前确认旧引擎归属和空队列；其他进程启动的引擎需要由使用者先关闭。新版启动或兼容检查失败时恢复旧设置，并尝试恢复本客户端原有引擎。若恢复也失败，界面如实显示原因。首次接入失败不会登记为可用环境。

更新保留旧版本、图库与任务。已校验但未能激活的新版本也会保留，下次重试先重新校验并复用；不会为恢复而删除仍可能被进程占用的目录。接入已有目录失败时不删除或迁移该目录。

## 分发与验收

当前仅开放夸克渠道。百度入口即使出现在旧发布清单中也保持置灰，主进程拒绝打开；不影响已下载 ZIP 的导入。

发布夸克运行包时，先准备该版本专用的夸克分享文件夹和提取码，使用以下命令生成 ZIP 与版本 JSON。示例中的版本、兼容客户端、路径及链接须替换成实际验收数据，不得直接用于发布：

```powershell
python tools/package_runtime.py --source <已验收的引擎目录> --acceptance-report <真实出图验收报告> --version <新引擎版本> --compatible-client <已验收的客户端版本> --quark-share-url <夸克官方分享链接> --quark-extraction-code <提取码> --out <独立输出目录>
```

无提取码时省略 `--quark-extraction-code`。工具生成的 JSON 包含 ZIP 大小、SHA256、展开大小和确切兼容版本，`archive.url=null`，下载入口仅含夸克。将 ZIP 上传到该分享文件夹，JSON 发布到可直接读取的 HTTPS 地址，并把该地址写入 `desktop/runtime-feed.json` 的 `manifestUrl` 后构建客户端。后续引擎单独更新只需更新同一版本信息地址，客户端无需重新安装。

正式验收依次检查：新电脑客户端获取版本信息 → 打开实际夸克分享页 → 官方客户端下载完整 ZIP → 回客户端导入 → 归档与文件校验 → 切换并启动新引擎 → 实际预览和放大输出。小夹具只验证前半段安装机制，不代表完整引擎和网盘下载已验收。

目前约 83.7 GB 的旧 `vivid-comfy-0.3.0` ZIP 早于后续预览修正，不能作为当前客户端的新电脑交付包。需要按当前节点、模型和工作流验收结果制作新引擎版本，并在干净环境完成真实预览和放大输出，再交付离线或在线渠道。

版本清单使用 GitHub 的 updates/engine.json，客户端安装包使用 GitHub Releases，正式夸克目录已配置，百度保持禁用；不要求网盘向客户端提供大包直链。完整包由官方客户端下载，下载续传归网盘客户端负责。相关协议见 [运行包契约](runtime-package-contract-v1.md)。小夹具测试与本机已有目录接入均不代替真实新电脑安装和出图验收。
