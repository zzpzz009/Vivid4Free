# 工作流封装与私有构建

目标是防止安装后从目录直接复制明文工作流。客户端内置加密压缩资源，在主进程内存中还原并提交给本机 ComfyUI，不把原件释放成 JSON，也不向前端提供获取完整工作流的接口。

密钥随客户端交付，这属于提高复制门槛，不构成防逆向承诺。执行请求、ComfyUI 队列、历史和输出元数据仍可能包含节点图；本次没有修改这些接口或保存节点。

## 私有输入

默认目录为仓库同级的 `VividPrivate/workflows`，包含 `preview.json` 和 `upscale.json` 两份 API 图。需要换目录时设置 `VIVID_WORKFLOW_SOURCE_DIR`。原件、来源记录与工作流生成脚本保存在 `VividPrivate`，不在 Git 仓库内。旧前端模板归档到其中的 `legacy-client-json`，本地客户端不再导入这些未开放的旧版远程生成模板。

保留原件用于继续在 CF 中编辑；封装只改变存储方式，不改变节点、连接、默认参数、上传缩图或保存行为。更新原件后重新构建客户端即可。

## 构建与验证

执行 `npm --prefix desktop run pack`，构建工具会生成被 Git 忽略的 `desktop/engine-data.dat`，核对还原字节的 SHA256，再打入安装包。缺少私有输入时构建失败，不使用旧资源冒充新版本。可单独执行 `node tools/build-workflows.cjs` 后运行 `npm --prefix desktop test`。封装器损坏、缺失与任务隔离测试使用合成图；现有预览、放大回归还需本机私有图。

CF 运行包只分发执行环境、节点和模型，不再附带本产品的 `workflows/*.json`。发布验收仍对照私有原件的 SHA256 和真实输出，不降低原有验收要求。

## Git 边界

发布检查会拒绝原始图、工作流生成脚本和生成资源进入 Git。安装包包含封装资源，但不提交到源码仓库。本次仅停止当前树和未来提交中的分发，不重写已有提交或已发布的历史；旧版本及历史中的工作流仍可能被获取。
